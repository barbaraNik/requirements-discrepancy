# AS-IS: Претензионный процесс (работа с расхождениями в поставке)

**Триггер:** Найдены расхождения в поставке.
 
**1. Фиксация расхождений.** Приёмщик отмечает на распечатанном документе позицию и количество расхождений.
 
**2. Развилка: есть ли вопросы по товарам из расходной?**
 
- **Да** → связаться с представителем из ВЭД → согласовать вопросы → далее к шагу 3.
- **Нет** → сразу к шагу 3.

**3. Создание задачи в Битрикс.**
 
**4. Фотофиксация.** Сделать фото распечатанного листа с отмеченными расхождениями.
 
**5. Передача в ВЭД.** Отправить фото и задачу с описанием в отдел ВЭД.
 
**6. Создание претензии для поставщика.** Далее параллельно:
 
- Сделать в 1С претензию.
- В свободной форме сохранить номер претензии.

**7. Сбор пакета документов по поставке.**
 
**8. Отправка претензии поставщику.**
 
**9. Ожидание ответа — таймер не более 1 месяца.**
 
**10. Развилка: поставщик ответил?**
 
- **Нет** → повторно направить пакет документов → снова ждать не более 1 месяца → цикл обратно к проверке ответа.
- **Да** → следующая развилка.

**11. Развилка: поставщик создал ответ в виде коммерции/уступки?**
 
- **Нет** → согласовать условия с руководством → возврат к развилке «ответил ли поставщик» (повторная итерация переговоров).
- **Да** → зафиксировать в свободной форме претензию на «Исполнено» и указать сумму компенсации при необходимости → отметить в 1С статус претензии «Уступка» → **конец: претензия закрыта.**

## Узкие места
 
- **Бумажная фиксация** — расхождения отмечаются ручкой на распечатке, потом фотографируются телефоном.
- **Дублирование данных** — номер претензии сохраняется «в свободной форме» отдельно от 1С, нет единого реестра.
- **Долгий цикл ожидания** — 1 месяц на ответ поставщика, при отсутствии ответа — ещё месяц. Претензия может висеть месяцами. На практике так и получается.
- **Ручная эскалация** — согласование с руководством при отказе поставщика не формализовано, нет SLA.
- **Данные в трёх системах** — Битрикс (задача), 1С (претензия), свободная форма (номер). Нет единой точки правды.
