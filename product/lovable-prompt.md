1. ЧТО ЭТО
Веб-прототип модуля претензий к поставщикам для отдела ВЭД оптового импортёра. Цель прототипа — проверить, что менеджер ВЭД быстро видит, чего не хватает в пакете документов по претензии, и закрывает пробелы. Интерфейс на русском.

2. ПОЛЬЗОВАТЕЛЬ
Менеджер ВЭД, который готовит претензии к поставщикам. Других ролей в прототипе нет: склад, продакт-менеджеры и сервисная служба — источники претензий и адресаты запросов, их экраны не нужны.

3. ЭКРАНЫ
Экран 1. Лента претензий: претензии от склада, продакт-менеджеров и сервисной службы. У каждой: номер претензии, поставщик, номер заказа, источник и индикатор полноты: «Пакет полный» (зелёный), «Не хватает: N» (красный) или «Пакет готов» (серый, если менеджер уже нажал кнопку). Клик открывает карточку.

Экран 2. Карточка претензии: номер претензии, поставщик, номер заказа, дата приёмки, источник, таблица позиций с расхождениями. Чек-лист документов пакета: у каждого пункта статус «Есть», «Нет» или «Запрошено»; пункты со статусом «Нет» подсвечены красным. Для каждого пункта можно загрузить файл — после загрузки статус становится «Есть». Для пунктов, которые закрывает другой человек, есть кнопка «Запросить у …» с нужным адресатом. Поле «Пожелания по компенсации». Кнопка «Пакет готов». Кнопка «Назад к ленте».

4. ДАННЫЕ

Претензия:
- номер претензии (совпадает с номером претензии в 1С)
- поставщик
- номер заказа (един для нас и поставщика; у поставщика может отличаться префикс)
- дата приёмки
- источник: «Склад», «Продакт-менеджер», «Сервисная служба»
- пожелания по компенсации (текст, может быть пустым)
- индикатор полноты пакета (вычисляется по чек-листу)
- признак «Пакет готов» и дата нажатия кнопки

Позиция с расхождением (принадлежит претензии):
- артикул
- наименование товара
- тип расхождения: недостача, повреждение, пересорт, брак, недокомплект
- количество по документам
- количество фактически
- единица измерения

Документ пакета (принадлежит претензии):
- тип: фото расхождения, фото артикула/шильдика, инвойс, упаковочный лист, контракт
- статус: «Есть», «Нет», «Запрошено»
- файл (если загружен; достаточно хранить имя файла)
- у кого запрошено: «Склад», «Продакт-менеджер», «Сервисная служба»
- дата запроса

5. ПРАВИЛА
- Претензия содержит только позиции с расхождениями.
- Пакет полный, если есть: фото расхождения, фото артикула/шильдика, инвойс, упаковочный лист, контракт.
- Если источник — «Продакт-менеджер» или «Сервисная служба», в чек-листе есть дополнительный обязательный пункт «Пожелания по компенсации». Он считается закрытым, когда поле заполнено.
- Фото расхождения есть всегда (приходит со склада).
- Фото артикула/шильдика можно запросить у склада. Пожелания по компенсации можно запросить у источника претензии (продакт-менеджера или сервисной службы). После запроса пункт получает статус «Запрошено» с датой.
- Инвойс, упаковочный лист и контракт менеджер находит сам и загружает файлом; кнопки «Запросить» для них нет.
- Кнопка «Пакет готов» активна, только когда каждый пункт чек-листа в статусе «Есть» или «Запрошено». Если неактивна — рядом подсказка, сколько пунктов осталось.
- Индикатор полноты в ленте обновляется сразу после изменений в карточке.

7. ЧЕГО НЕ ДЕЛАТЬ
Без авторизации и базы данных: данные хранятся в приложении. Не делать: генерацию претензионного письма, отправку писем, статусы после «Пакет готов», сроки претензий и предупреждения, суммы и цены, редактирование позиций, дашборды и отчёты.
