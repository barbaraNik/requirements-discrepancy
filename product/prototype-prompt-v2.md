1. ЧТО ЭТО
Веб-прототип модуля претензий к поставщикам для отдела ВЭД оптового импортёра. Цель прототипа — проверить, что менеджер ВЭД быстро видит, чего не хватает в пакете документов по претензии, и закрывает пробелы. Интерфейс на русском. Одностраничное приложение без бэкенда.

2. ПОЛЬЗОВАТЕЛЬ
Менеджер ВЭД, который готовит претензии к поставщикам. Других ролей в прототипе нет: склад, продакт-менеджеры и сервисная служба — источники претензий и адресаты запросов, их экраны не нужны.

3. ДВА УРОВНЯ СТАТУСОВ
Этап — где претензия в работе. Показывается вкладками с числом претензий. Меняет менеджер.
- «Новые» — претензия пришла, менеджер её ещё не взял.
- «В работе» — менеджер начал работу: нажал «Взять в работу» или сделал первое действие в карточке (загрузка, запрос, ввод пожеланий по компенсации).

Статус пакета — что с документами. Показывается меткой в списке и в карточке на обоих этапах, чтобы сразу было видно, где всё есть, а где не хватает. Меняется автоматически по чек-листу:
- «Не хватает: N» (красный) — есть пункты со статусом «Нет»;
- «Ожидает документы» (жёлтый) — пунктов «Нет» нет, но есть «Запрошено»;
- «Пакет полный» (зелёный) — все пункты «Есть».

4. ЭКРАНЫ
Экран 1. Список претензий. Сверху вкладки «Новые (N)» и «В работе (N)», число обновляется сразу. В списке у каждой претензии: номер, поставщик, номер заказа, дата приёмки, источник. На обеих вкладках — цветная метка статуса пакета; на вкладке «В работе», если менеджер нажал «Сборка завершена», серая метка «Сборка завершена». Клик открывает карточку.

Экран 2. Карточка претензии: номер, поставщик, номер заказа, дата приёмки, источник, этап, статус пакета, таблица позиций с расхождениями.
- Если претензия на этапе «Новые» — вверху кнопка «Взять в работу», она переводит претензию на этап «В работе». Действия в чек-листе доступны сразу, первое действие тоже переводит претензию на этап «В работе».
- Чек-лист документов пакета: у каждого пункта статус «Есть», «Нет» или «Запрошено»; пункты «Нет» подсвечены красным.
- Для каждого пункта можно загрузить файл — статус становится «Есть». Для пунктов «Есть» — кнопка «Открыть»: загруженный файл открывается в новом окне, для тестовых документов без файла — заглушка с названием документа.
- Для пунктов, которые закрывает другой человек, — кнопка «Запросить у …» с нужным адресатом; после нажатия статус «Запрошено» с датой. У пункта «Запрошено» — кнопка «Отметить полученным», статус становится «Есть».
- Поле «Пожелания по компенсации» — только для претензий от продакт-менеджера и сервисной службы.
- Внизу кнопка «Сборка завершена» и подсказка, сколько пунктов осталось. Кнопка «Назад к списку».

5. ДАННЫЕ
Претензия: номер (10 цифр, совпадает с номером в 1С), поставщик, номер заказа (един для нас и поставщика; у поставщика может отличаться префикс), дата приёмки, источник («Склад», «Продакт-менеджер», «Сервисная служба»), этап («Новые», «В работе»), пожелания по компенсации (текст, может быть пустым), статус пакета (вычисляется), признак и дата «Сборка завершена».

Позиция с расхождением (принадлежит претензии): артикул, наименование товара, тип расхождения (недостача, повреждение, пересорт, брак, недокомплект), количество по документам, количество фактически, единица измерения.

Документ пакета (принадлежит претензии): тип (фото расхождения, фото артикула/шильдика, инвойс, упаковочный лист, контракт), статус («Есть», «Нет», «Запрошено»), имя файла, у кого запрошено, дата запроса.

6. ПРАВИЛА
- Претензия содержит только позиции с расхождениями.
- Пакет полный, если есть: фото расхождения, фото артикула/шильдика, инвойс, упаковочный лист, контракт.
- Если источник — «Продакт-менеджер» или «Сервисная служба», в чек-листе есть дополнительный обязательный пункт «Пожелания по компенсации». Он закрыт, когда поле заполнено.
- Фото расхождения есть всегда (приходит со склада).
- Фото артикула/шильдика запрашивается у склада. Пожелания по компенсации — у источника претензии.
- Инвойс, упаковочный лист и контракт менеджер находит сам и загружает файлом; кнопки «Запросить» для них нет.
- На этапе «Новые» все действия доступны; первое действие (загрузка, запрос, ввод пожеланий по компенсации) автоматически переводит претензию на этап «В работе». Кнопка «Открыть» доступна на любом этапе.
- Кнопка «Сборка завершена» активна, когда нет пунктов со статусом «Нет» (все «Есть» или «Запрошено»).
- Статус пакета, метки и числа во вкладках обновляются сразу.

8. ДИЗАЙН
Лаконично. Светлый фон #F8FAFC, белые карточки с тонкой рамкой, без теней и градиентов, скругление 8px. Светлая боковая панель с одним пунктом «Претензии». Один акцентный синий цвет только для главных кнопок. Статусы — небольшие приглушённые «таблетки» с текстом, смысл не только цветом. Шрифт Inter, текст 14–16px. Иконки lucide, без эмодзи. Кнопки и поля не меньше 40px, видимый фокус с клавиатуры.

9. ЧЕГО НЕ ДЕЛАТЬ
Без авторизации и базы данных: данные хранятся в приложении (Supabase не подключать). Не делать: этапы после «В работе» (отправка поставщику, ответ, согласование, закрытие), генерацию претензионного письма, отправку писем, сроки претензий и предупреждения, суммы и цены, редактирование позиций, дашборды и отчёты.
